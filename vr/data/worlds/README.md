# World data

Authored source of truth for what a world is made of, compiled into frozen runtime modules. Do not edit the compiled files.

**Invariant:** nothing in `vr/sim/` may name a specific body except as a validation case, or as an override that carries a `why`. Selection is by axes and flags.

## Files

| File | What it is |
|---|---|
| `kinds.json` | **Generated audit.** Committed kind-resolution histogram. Regenerated by `scripts/worldspace.mjs`. Tests fail if a live audit drifts. Do not hand-edit. |
| `substrates.json` | Surface materials. Compiled by `scripts/substrates.mjs` into `vr/sim/substrates.js`. |
| `cover.json` | Cover kinds (frost, dust, lag, tholin, sulfur, evaporite, rays, mats). Compiled by `scripts/cover.mjs` into `vr/sim/coverTable.js`. |
| `processes.json` | Geomorphic processes. Compiled with `landforms.json` by `scripts/landgram.mjs` into `vr/sim/landGrammar.js`. |
| `landforms.json` | Landforms. Gates are axes and flags, not a name regex. Stamps and ice-shell ops place them. |
| `columns.json` | Column recipes. Compiled by `scripts/columns.mjs` into `vr/sim/columnTable.js`. The recipe stamps the per-cell stack at generate; processes then change it. |
| `definitions.json` | **The join.** Selection rules that tie materials, cover, column, art direction and paint to a world. Compiled by `scripts/worlddef.mjs` into `vr/sim/worldDef.js`. |
| `paint.json` | Surface colour ramps per geology kind. Compiled by `scripts/paint.mjs` into `vr/sim/paintTable.js`. Evaluated by `paintEval.js`. |
| `stamps.json` | Hypsometry as landform grammar: ops + placements. Compiled by `scripts/stamps.mjs` into `vr/sim/stampTable.js`. Evaluated by `stampApply.js`. Old `stamp*` functions live in `stampFixtures.js` as validation cases. |
| `kindRules.json` | Ordered name → geology kind. Compiled by `scripts/kindrules.mjs` into `vr/sim/kindTable.js`. Axis fallbacks stay in `planetKind.js`. |
| `iceshell.json` | Ice-shell maps as fill/add/set of landform masks. Compiled by `scripts/iceshell-data.mjs` into `vr/sim/shellTable.js`. Evaluated by `shellApply.js`. Old `paint*` functions live in `shellFixtures.js` as validation cases. |
| `features.json` | Named landforms keyed on catalogue body, matched to `surfaceKeyAt`. Same compiler. |
| `world.schema.json` | Contract for a definition: required fields, units, needs, look. |
| `epochs.json` | Startable worlds (clock, gases, ice, landscape, palette). Compiled by `scripts/epochs.mjs` into `vr/sim/epochTable.js`. |

`vr/data/techno/sources.json` is the energy-source table (biomass … orbital). Compiled by `scripts/techno.mjs` into `vr/sim/technoTable.js`.

Run **all** compilers with `node scripts/data.mjs` (or `npm run data` from `vr/`). That also prints `dataratio` / `newworldcost` and writes `site/world-data.html`. The compiled `worldDef.js` carries `WORLDDEF_HASH`; tests fail if the JSON changed and nobody compiled.

Surface colour is authored under the Sun. `vr/sim/illum.js` multiplies it by the host star (camera white-balanced to 5772 K). Solar-System worlds do not shift. `pictureDisc.js` is the CPU contact sheet.

## Adding a world

Adding a Solar-System-like body should be a JSON review, not a code review. Named kinds live in `kindRules.json`. Surface colour is `paint.json`. Rocky height is `stamps.json`. Ice-shell maps are `iceshell.json`. `newworldcost` is the leftover named-kind regex count in `planetKind.js` (should be 0).

1. If the axes already select a definition (ice shell, heat-pipe, airless, dusty basalt…), you are done: no new file.
2. If they do not, add a **rule** to `definitions.json` with `needs` on axes/flags, not a body name. An override with a `why` is allowed when the world is a genuine exception (Iapetus).
3. Named features go in `features.json` keyed on the catalogue name, with a `key` that `surfaceKeyAt` already paints.
4. A new appearance ramp goes in `paint.json`, not a lambda in `planetLook.js`.
5. A new Solar-System name goes in `kindRules.json` (and a stamp or ice recipe if the shape is new).
6. `node scripts/data.mjs` — the validator refuses unknown column recipes, unknown materials, and an override without a why.

A world definition is shareable later; the join must stay a small set of rules. One JSON per body is 64 lambdas with a different extension.

## Adding a substrate

1. Give it an `id` in camelCase and a display `name`.
2. Set `class` (`rock`, `ice`, `organics`, `salt`, `metal`, `fluid`, `envelope`).
3. Fill density (kg/m³), albedo, `k` (W/m/K), `strength` (MPa), `erode` (Earth rain = 1), `rgb`. Units live on the file and in `world.schema.json`.
4. Optional `ramp` with `dry` / `wet` / `ice` triples — the overlay samples it.
5. Ices and volatiles: `meltK`, `boilK`, `tripleK`, `tripleBar`, `LsubJmol`. Optional `criticalK` / `criticalBar`, `convectK` (solid flows above this T).
6. Giants: `noSurface: true` on `envelope`.
7. Tag `measured` / `fitted` / `invented` and write `why` in one sentence.
8. Keep indices 0–7 as the eight Earth rocks (`basalt` … `glacialTill`) so `W.rock` maps without a table.
9. Run `node scripts/substrates.mjs` — the validator refuses duplicate ids, unknown tags, and a missing Earth-rock prefix.

Physics (`phaseAt`, `rheologyAt`, stamping `W.substrate`) lives in `vr/sim/substrateField.js`. The per-cell stack lives in `vr/sim/colstack.js`. The JSON is numbers; the compiler does not invent a cycle.

A nitrogen glacier that was stamped as `sediment` is the kind of error the table exists to end.

## Adding a cover kind

1. Give it an `id` and a display `label`.
2. Set `albedoFine` and `albedoCoarse` (0–1). Fine must be ≥ coarse — grain darkens ice and dust.
3. `rgb`, tag `measured` / `fitted` / `invented`, and a `why` sentence. Optional `cite`.
4. Run `node scripts/cover.mjs`.

Physics (`coverAt`, `stampCover`, grain, weathering) lives in `vr/sim/cover.js`. The JSON is albedos; the compiler does not invent a dust cycle.

## Adding a process or landform

1. Add a process to `processes.json` (`id`, `name`, `rate`, `tag`, `why`). Rate is relative to Earth rain = 1.
2. Add a form to `landforms.json`: `process` must exist, `scaleKm` / `reliefM` / `rgb`, optional `hint`, `needs` keyed on axes and flags (interior, volatile, airless, iceShell, teq, gravity, resurface, tidal) — not a body name.
3. Tag `measured` / `fitted` / `invented` and write `why` in one sentence.
4. Run `node scripts/landgram.mjs`.

Runtime (`landformPalette`, `formAtCell`, `stampLandforms`) lives in `vr/sim/landform.js`. The heightfield is still the 27 stamps. Earth does not stamp. Giants get an empty palette. Exo palettes are marked invented. `craterCounts` is computed from age/resurface/g and is not wired into `stampCraters`.

## Adding a column recipe

1. Add a layer to `columns.json` (`id`, `name`, `rgb`, optional `substrate` from `substrates.json`, tag, why).
2. Add a recipe: `needs` keyed on axes and flags (interior, volatile, airless, iceShell) — not a body name. First match wins.
3. Layer specs take `depthKm`, optional `vary` (`lid` / `ocean`) and `when` (`hpIce` / `clathrate`).
4. Tag `measured` / `fitted` / `invented` and write `why` in one sentence.
5. Run `node scripts/columns.mjs`.

Runtime (`recipeOf`, `columnAt`) lives in `vr/sim/columnField.js`. `stampStack` in `vr/sim/colstack.js` writes the recipe into a fixed eight-layer per-cell array (thickness in metres). Ice-shell thicknesses follow `W.shellLid` / `W.shellOcean`. Earth stamps from `W.rock`. Giants are empty. Erosion peels the top; deposition writes sediment.

## Adding an epoch

1. Add a row to `epochs.json`: `id`, `name`, `world` (`earth` / `venus` / `mars`), `deepTime`, `startMaBP` (Ma before present), optional `gases`, `landscape`, `iceBoost`, `oceanRgb`.
2. Tag `measured` / `fitted` / `invented`, a `why` sentence, and a `cite`.
3. Run `node scripts/epochs.mjs`. Present Earth must stay a no-op (no gases) so the golden hash holds.

Runtime (`availableEras`, `eraPatch`, `applyEpochAtGenerate`) lives in `vr/sim/epoch.js`. Palaeogeography is an existing landscape archetype, not reconstructed plates.
